# 有界チャネルと無制限チャネル

これまでは無制限（unbounded）チャネルを使用してきました。\
好きなだけメッセージを送信でき、チャネルはそれらを収容するために際限なく大きくなります。\
しかし、複数生産者・単一消費者（mpsc）のシナリオでは、これが問題になる可能性があります。消費者（コンシューマ）がメッセージを処理できる速度よりも速いペースで生産者（プロデューサ）がメッセージをキューに追加し続けると、チャネルは肥大化し続け、利用可能なすべてのメモリを消費してしまう恐れがあるからです。

私たちの推奨は、本番システムでは無制限チャネルを**決して使用しない**ことです。\
代わりに**有界チャネル (bounded channel)** を使用して、キューに入れることができるメッセージの数に常に上限を設けるべきです。

## 有界チャネル (Bounded channels)

有界チャネルは固定の容量（キャパシティ）を持っています。\
0より大きい容量を指定して `sync_channel` を呼び出すことで作成できます：

```rust
use std::sync::mpsc::sync_channel;

let (sender, receiver) = sync_channel(10);
```

`receiver` は以前と同じ `Receiver<T>` 型です。\
一方、`sender` は `SyncSender<T>` のインスタンスになります。

### メッセージの送信

`SyncSender` を介してメッセージを送信するには、2つの異なるメソッドがあります：

- `send`：チャネルに空きがある場合、メッセージをキューに入れて `Ok(())` を返します。\
  チャネルが満杯の場合、空きができるまでスレッドをブロックして待機します。
- `try_send`：チャネルに空きがある場合、メッセージをキューに入れて `Ok(())` を返します。\
  チャネルが満杯の場合、`Err(TrySendError::Full(value))` を返します（ここで `value` は送信できなかったメッセージです）。

ユースケースに応じて、適切な方を使い分けることになります。

### バックプレッシャー (Backpressure)

有界チャネルを使用する主な利点は、一種の**バックプレッシャー（背圧）**を提供してくれることです。\
消費者の処理が追いつかない場合、生産者のペースを強制的に落とさせます。
このバックプレッシャーはシステム全体に伝播し、アーキテクチャ全体に影響を与えて、エンドユーザーからの過剰なリクエストによってシステムがパンクするのを防ぐことができます。
