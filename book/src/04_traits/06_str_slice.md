# 文字列スライス (String slices)

これまでの章を通して、`"To-Do"` や `"A ticket description"` のような**文字列リテラル (string literals)** がコード内で数多く使われているのを目にしてきました。
それらの後ろには常に `.to_string()` や `.into()` の呼び出しが続いていました。なぜそうしていたのかを理解する時が来ました！

## 文字列リテラル

生のテキストをダブルクォーテーション `"` で囲むことで、文字列リテラルを定義します：

```rust
let s = "Hello, world!";
```

`s` の型は `&str`、つまり**文字列スライスへの参照 (reference to a string slice)** です。

## メモリレイアウト

`&str` と `String` は異なる型であり、互換性はありません。\
[以前の探求](../03_ticket_v1/09_heap.md)から、`String` のメモリレイアウトを思い出してみましょう。
次のコードを実行すると：

```rust
let mut s = String::with_capacity(5);
s.push_str("Hello");
```

メモリ上では次のような状況になります：

```text
         +---------+--------+----------+
スタック | pointer | length | capacity | 
         |  |      |   5    |    5     |
         +--|------+--------+----------+
            |
            |
            v
         +---+---+---+---+---+
ヒープ:  | H | e | l | l | o |
         +---+---+---+---+---+
```

覚えているかもしれませんが、`&String` がメモリ上でどのように配置されるかについても[以前確認しました](../03_ticket_v1/10_references_in_memory.md)：

```text
     --------------------------------------
     |                                    |         
+----v----+--------+----------+      +----|----+
| pointer | length | capacity |      | pointer |
|    |    |   5    |    5     |      |         |
+----|----+--------+----------+      +---------+
     |        s                          &s 
     |       
     v       
   +---+---+---+---+---+
   | H | e | l | l | o |
   +---+---+---+---+---+
```

`&String` は、`String` のメタデータが保存されているメモリ位置を指します。\
ポインタを辿ると、ヒープに割り当てられたデータに辿り着きます。具体的には、文字列の最初のバイトである `H` に辿り着きます。

では、`s` の**部分文字列 (substring)**（例えば `Hello` の中の `ello`）を表す型が欲しい場合はどうすればよいでしょうか？

## 文字列スライス

`&str` は文字列への**ビュー (view)** であり、他の場所に保存されている一連のUTF-8バイト列への**参照**です。
例えば、次のようにして `String` から `&str` を作成できます：

```rust
let mut s = String::with_capacity(5);
s.push_str("Hello");
// 最初のバイトをスキップして、`String` から
// 文字列スライス参照を作成します。
let slice: &str = &s[1..];
```

メモリ上では、次のようになります：

```text
                      s                              slice
         +---------+--------+----------+      +---------+--------+
スタック | pointer | length | capacity |      | pointer | length |
         |    |    |   5    |    5     |      |    |    |   4    |
         +----|----+--------+----------+      +----|----+--------+
              |        s                           |  
              |                                    |
              v                                    | 
            +---+---+---+---+---+                  |
ヒープ:     | H | e | l | l | o |                  |
            +---+---+---+---+---+                  |
                  ^                                |
                  |                                |
                  +--------------------------------+
```

`slice` はスタック上に2つの情報を保存します：

- スライスの最初のバイトへのポインタ。
- スライスの長さ。

`slice` はデータを所有しておらず、単にそれを指しているだけです。つまり、`String` のヒープ割り当てデータへの**参照**です。\
`slice` がドロップされても、ヒープ割り当てデータは解放されません。なぜなら、そのデータは依然として `s` によって所有されているからです。
`slice` に `capacity`（容量）フィールドがないのもそのためです。データを所有していないため、そのデータのためにどれだけのスペースが割り当てられたかを知る必要がなく、自身が参照しているデータのことだけを気にすればよいのです。

## `&str` と `&String` の使い分け

経験則として、テキストデータへの参照が必要なときはいつでも、`&String` ではなく `&str` を使用してください。\
`&str` の方が柔軟性が高く、一般的にRustのコードにおいてよりイディオマティック（Rustらしい書き方）であるとみなされています。

メソッドが `&String` を返す場合、返そうとしている参照と**完全に一致する**ヒープ割り当てされたUTF-8テキストがどこかに存在することを約束していることになります。\
一方、メソッドが `&str` を返す場合は、はるかに大きな自由度があります。*どこかに*テキストデータの塊があり、その一部（サブセット）が必要なものと一致しているため、そこへの参照を返している、と言っているに過ぎないからです。
