# NULL可能性 (Nullability)

先ほどの `assigned_to` メソッドの実装はかなり乱暴です。未着手（To-Do）や完了（Done）のチケットに対してパニックを起こすのは、到底理想的とは言えません。\
**Rustの `Option` 型**を使えば、もっとうまく表現できます。

## `Option`

`Option` は、**NULLになり得る値（値が存在しない可能性がある状態）**を表すRustの型です。\
これはRustの標準ライブラリで定義されている列挙型（`enum`）です：

```rust
enum Option<T> {
    Some(T),
    None,
}
```

`Option` は、値が存在する (`Some(T)`) かもしれないし、存在しない (`None`) かもしれないという概念を型として表現します。\
また、**両方のケースを明示的に処理する**ことを強制します。値が存在しない可能性がある値を扱っているときに `None` のケースの処理を忘れると、コンパイルエラーになります。\
これは、`null` チェックを忘れて実行時エラーを引き起こしてしまう他の言語の「暗黙的な」NULL可能性と比べて、大幅な改善です。

## `Option` の定義

`Option` の定義では、これまで見たことのないRustの構文が使われています。それが**タプル風のバリアント (tuple-like variants)** です。

### タプル風のバリアント

`Option` には `Some(T)` と `None` の2つのバリアントがあります。\
`Some` は**タプル風のバリアント**であり、**名前のないフィールド**を保持するバリアントです。

タプル風のバリアントは、保存するフィールドが1つだけの場合、特に `Option` のような「ラッパー（包み込む）」型を扱う場合によく使用されます。

### タプル構造体 (Tuple-like structs)

これは列挙型に特有のものではなく、タプル風の構造体（タプル構造体）を定義することもできます：

```rust
struct Point(i32, i32);
```

`Point` インスタンスの2つのフィールドには、位置インデックスを使ってアクセスできます：

```rust
let point = Point(3, 4);
let x = point.0;
let y = point.1;
```

### タプル (Tuples)

まだタプル自体を見ていないのに「タプル風」と言うのは少し変ですね！\
タプルは、Rustのプリミティブ型のもう1つの例です。
タプルは、（異なる型の可能性もある）固定個の値を1つにグループ化します：

```rust
// 同じ型の2つの値
let first: (i32, i32) = (3, 4);
// 異なる型の3つの値
let second: (i32, u32, u8) = (-42, 3, 8);
```

構文はシンプルです。丸括弧の中に値の型をカンマ区切りで並べるだけです。
ドット記法とフィールドインデックスを使用して、タプルの各フィールドにアクセスできます：

```rust
assert_eq!(second.0, -42);
assert_eq!(second.1, 3);
assert_eq!(second.2, 8);
```

タプルは、専用の構造体型をわざわざ定義するほどではないときに、複数の値を手軽にまとめるのに便利な方法です。
