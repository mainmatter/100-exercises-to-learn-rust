# ケースバイケースの振る舞い

`overflow-checks` は大雑把なツールです。プログラム全体に影響を与えるグローバルな設定だからです。\
文脈に応じて整数オーバーフローを異なる方法で処理したいことはよくあります。ラッピング（折り返し）が正しい選択である場合もあれば、パニックさせる方が望ましい場合もあります。

## `wrapping_` メソッド

`wrapping_` メソッド[^method]を使用することで、演算ごとにラッピング演算を選択できます。\
例えば、`wrapping_add` を使用すると、ラッピングありで2つの整数を加算できます：

```rust
let x = 255u8;
let y = 1u8;
let sum = x.wrapping_add(y);
assert_eq!(sum, 0);
```

## `saturating_` メソッド

あるいは、`saturating_` メソッドを使用して**飽和演算 (saturating arithmetic)** を選択することもできます。\
飽和演算は、ラップアラウンドする代わりに、その整数型の最大値または最小値を返します。
例えば：

```rust
let x = 255u8;
let y = 1u8;
let sum = x.saturating_add(y);
assert_eq!(sum, 255);
```

`255 + 1` は `256` であり、`u8::MAX` よりも大きいため、結果は `u8::MAX` (255) になります。\
アンダーフローの場合は逆のことが起こります。`0 - 1` は `-1` であり、`u8::MIN` よりも小さいため、結果は `u8::MIN` (0) になります。

`overflow-checks` プロファイル設定を通じて飽和演算を得ることはできません。算術演算を実行する際に、明示的に選択する必要があります。

[^method]: メソッドとは、特定の型に「紐づいた」関数だと考えることができます。
メソッド（およびその定義方法）については次の章で扱います。
